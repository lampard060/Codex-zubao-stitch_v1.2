# 足宝项目说明

## 1. 项目结构

### 官网与登录

| 页面 | 文件路径 | 说明 |
| --- | --- | --- |
| 官网首页 | `app/index.html` | 品牌入口页，展示产品定位与角色入口。 |
| 登录页 | `app/login.html` | 统一登录入口，提供商家端、技师端与消费者入口展示。 |

### 商家端

| 页面 | 文件路径 | 说明 |
| --- | --- | --- |
| 首页 | `app/merchant-dashboard.html` | 查看今日订单、营收、在岗技师和营业趋势。 |
| 技师管理 | `app/merchant-technicians.html` | 处理技师加入申请、在店状态和技师列表管理。 |
| 订单管理 | `app/merchant-orders.html` | 查看上钟记录、订单状态与当日订单信息。 |
| 经营统计 | `app/merchant-analytics.html` | 查看收入、工资支出、净营收、趋势与技师业绩。 |
| 工资明细 | `app/merchant-payroll.html` | 作为统计页二级页面，处理工资规则设置、工资核算与发薪复核。 |
| 门店设置 | `app/merchant-settings.html` | 管理门店信息、技师加入二维码与套餐信息。 |

### 技师端

| 页面 | 文件路径 | 说明 |
| --- | --- | --- |
| 工作台 | `app/technician-home.html` | 查看当前工作状态、最近结算与门店信息。 |
| 收益统计 | `app/technician-earnings.html` | 查看收益趋势与收益记录。 |
| 我的资料 | `app/technician-profile.html` | 管理个人资料、当前签约门店与门店记录。 |

## 2. 业务边界

- 商家端用于门店日常经营管理，重点覆盖技师、订单、统计、工资和门店设置。
- 技师端用于个人工作协同，重点覆盖工作状态、收益查看和资料维护。
- 技师拥有独立账号，个人资料由技师本人维护。
- 技师同一时间仅可签约一家门店，签约期间不可再申请其它门店，解约后恢复申请资格。
- 商家不编辑技师个人资料，仅处理加入审核、在店状态和门店内协同管理。
- 工资模块属于经营统计的延伸能力，作为二级页面承接更适合日常使用习惯。
- 消费者入口当前保留品牌展示与入口位置，后续可用于预约与服务连接。

## 3. 页面流程

### 商家端流程

1. 登录后进入商家首页。
2. 在首页查看当日经营概况与进行中订单。
3. 在技师管理页处理加入申请并调整技师在店状态。
4. 在订单管理页查看和筛选上钟记录。
5. 在经营统计页查看收入、工资支出、净营收和技师业绩。
6. 从经营统计页进入工资明细页，完成工资规则设置与工资复核。
7. 在门店设置页维护门店信息、二维码与套餐信息。

### 技师端流程

1. 登录后进入工作台。
2. 在工作台查看当前状态、门店信息和最近结算记录。
3. 在收益统计页查看收益趋势与收益明细。
4. 在我的资料页维护个人资料，并查看当前签约门店与门店记录。

## 4. 页面语言规范

- 按钮动作统一使用“查看 / 修改 / 保存 / 审核 / 生成”等正式产品语言。
- 商家端订单状态统一为“服务中 / 已完成”。
- 技师工作状态统一为“在岗 / 待钟 / 服务中 / 休息”。
- 门店关系状态统一为“当前签约中 / 已锁定 / 解约后可申请”。
- 工资状态统一为“已开启 / 已生效 / 可追溯 / 已计入工资”。
- 官网首页与登录页保留 `ZuBao` 作为品牌英文标识，业务页统一使用“足宝”。

## 6. 后续开发建议

- 将当前静态数据抽离为统一的共享数据源，便于后续联调与替换。
- 接入真实的登录、门店、技师、订单与工资数据结构。
- 将页面逐步迁移为组件化前端结构，方便后续维护与扩展。
- 在消费者入口开放前，补充预约、到店与评价相关的业务设计与数据模型。
